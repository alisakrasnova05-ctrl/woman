# Карта выбранного места — Traveler's Glider

## Анализ и решение

Карта и таймлайн уже используют Leaflet и общий `selectedKey`. Ранее карта стартовала с Москвы, город устанавливался через `setView`, выбор события не сохранялся, а маркеры маршрута не выбирали связанное событие.

Изменены только `public/app.js` и `public/planner.js`. Модель и API не менялись. Календарь передаёт текущий день через `date`, а ссылки сохранённых событий — дополнительно через `event`. Все переходы используют существующий `/trip?trip=<id>`.

Приоритет открытия:

1. Явно открытое из календаря событие; для нового выбранного дня — событие этого дня с координатами. Фокус на точке, зум 15.
2. Сохранённый обзор данной поездки: центр, зум, выделенная точка/событие/перемещение и день. Перезагрузка того же URL события сохраняет вручную изменённый обзор.
3. Город поездки, зум 12.
4. Если города нет — все известные точки через `fitBounds`, одна точка — зум 15. Несколько городов отдельной моделью сейчас не поддерживаются, новая модель не добавлялась.
5. Без города и точек — общий вид и «Выберите город при создании путешествия».

Состояние хранится в `localStorage` под ключом `glider-map-v1:<tripId>`, обновляется после движения/масштабирования карты, при уходе и скрытии страницы. Повреждённое/недоступное хранилище не блокирует работу. Удалённое выбранное место не восстанавливается — используется город или точки маршрута. Автоматической геолокации нет.

Центрирование плавное, с учётом `prefers-reduced-motion`. Выбор маркера на карте выбирает связанное событие текущего дня; при необходимости открывает день первого связанного события. Точка без событий также выделяется и запоминается. Позиционирование и загрузка OSM-достопримечательностей сохранены.

## Ручная проверка

1. Создайте поездку с городом, откройте карту: центр на городе, зум 12. Геолокация не запрашивается.
2. Выберите событие с точкой на таймлайне: карта плавно приближается к ней, зум 15, маркер подсвечен.
3. Измените масштаб и сдвиньте карту. Вернитесь на главную и снова откройте карту этой поездки: обзор и выделение восстановлены. Повторите с перезагрузкой страницы.
4. Откройте другую поездку, измените её обзор. Вернитесь к первой: её состояние осталось независимым.
5. В календаре выберите день и нажмите «Карта маршрута»: при наличии события с точкой карта открывается на ней. Нажмите название сохранённого события в календаре: открывается именно оно с подсветкой в таймлайне.
6. Кликните маркер маршрута: связанное событие выделяется. Для точки без события проверить выделение и восстановление после повторного открытия.
7. Для поездки без города проверить одну/несколько точек; без города и точек — общий вид и подсказку.
8. В DevTools → Application испортите значение `glider-map-v1:<id>` и перезагрузите: корректный запасной вид без падения. Изменять значение следует после закрытия страницы карты, иначе обработчик ухода может записать актуальное состояние поверх ручного значения.
9. Заблокируйте API событий в DevTools и откройте карту: отображается сообщение об ошибке данных, сама карта остаётся доступной. Ошибки Overpass обрабатываются прежним способом.
10. Включите reduced-motion: центрирование происходит без полётной анимации.

## Проверено

Синтаксис обоих файлов, `git diff --check`. Chromium с подменённым API: город; изоляция поездок; восстановление центра/зума/выделения; явный переход к событию; перезагрузка URL события; маркер → таймлайн; отсутствие города; повреждённое и недоступное хранилище; ссылки календаря; ошибка загрузки событий. Тестовые данные в пользовательскую базу не записывались.
