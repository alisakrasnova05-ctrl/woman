# Поиск мест для планов Traveler's Glider

## Анализ и изменения

Уже работали серверный LLM-разбор с эвристическим fallback, автораспределение `PlanSchedule`, календарные черновики, маркеры предпросмотра и сохранение событий/точек через API. Старый геокодер возвращал один результат Nominatim без строгого ограничения страны и без подтверждения вариантов.

Добавлены серверные адаптеры 2ГИС Catalog, Яндекс Поиск организаций, Яндекс.Геокодер, Nominatim, Open-Meteo, выбор неоднозначного места и кэш поездки. Автораспределение, подтверждение дат, таймлайн, история, файлы, достопримечательности и удаление поездок используют прежние механизмы.

## Предоставленный ключ

Проверены реальные запросы без вывода ключа или URL с ключом:

- 2ГИС Catalog: HTTP 200, `meta.code=403`, `Authorization error, incorrect key.`
- Яндекс.Геокодер: HTTP 403, `Invalid api key`.
- Яндекс Поиск организаций: пригодный ответ не получен.

По UUID определить сервис нельзя. Работа платного поиска с этим ключом **не подтверждена**: 2ГИС и Яндекс.Геокодер его отклонили. Адаптеры подключены и проверены контролируемыми ответами; для реального платного поиска требуется действующий ключ с доступом к выбранному API. Сейчас реальный поиск работает через бесплатный fallback.

Ключ сохранён только в игнорируемом серверном `.env` (0600), `PLACES_PROVIDER=auto`. В коде, ответах API, документации, патче и логах его значения нет. Имеющийся LLM-токен не менялся. Для другого окружения заполнить `PLACES_API_KEY` на сервере и перезапустить `npm start`. Допустимые провайдеры: `auto`, `2gis`, `yandex`, `yandex-geocoder`, `none` (только бесплатные сервисы). `.env.example` содержит пустое поле ключа.

Документация подключения:

- https://docs.2gis.com/en/api/search/places/reference/3.0/items
- https://yandex.com/maps-api/docs/geosearch-api/request.html
- https://yandex.com/maps-api/docs/geocoder-api/request.html
- https://nominatim.org/release-docs/latest/api/Search/
- https://open-meteo.com/en/docs/geocoding-api

## Правила поиска

1. LLM извлекает название и время; координаты модели по-прежнему игнорируются.
2. Поиск выполняется backend. Календарь использует localStorage-кэш по поездке, городу, стране и координатам. Перед новым запросом — 500 мс; набор текста сам по себе не отправляется провайдерам.
3. Области: до 50 км от города → до 150 км → до 300 км → страна целиком. Это пространственный поиск соседних населённых пунктов без отдельного каталога городов. В каждой области сначала проверяются сервисы с ключом, затем Nominatim и Open-Meteo.
4. Проверяются координаты, фактическое расстояние и ISO-код страны. Nominatim получает `countrycodes`, `viewbox`, `bounded=1`, русский язык и User-Agent; запросы сериализуются с интервалом не менее 1100 мс. Результаты сортируются по расстоянию. Без страны или координат расширение поиска отключено, чтобы не искать произвольные места по всему миру.
5. Автоматически выбирается только один уверенный результат в городе поездки. Требуется совпадение значимого слова названия; общий запрос «музей» не становится уверенным только из-за одного ответа. Если локальность не указана, автоматический выбор допустим лишь не дальше 10 км от центра в локальной области поиска.
6. Несколько вариантов или любое иногороднее место требуют выбора. В списке — название, город, адрес и расстояние; местные варианты рекомендованы. Можно оставить план без места или повторить поиск.
7. Open-Meteo используется только для точного поиска населённых пунктов, а не для подмены музея координатами города.
8. Выбор обновляет прежний черновик и маркер на карте, включая соседнюю вкладку. Постоянная запись — прежней кнопкой сохранения с переходом на карту.

Кэш: найденные варианты — 24 часа, подтверждённое отсутствие — 60 секунд, сетевые ошибки не кэшируются. Явная кнопка повторного поиска обходит кэш. Размер ограничен; одинаковые параллельные запросы объединяются. Отказ авторизации приостанавливает адаптер на 30 минут, HTTP 429 — на минуту (ошибка в теле ответа 2ГИС — на 30 минут). Другие сервисы продолжают поиск. Есть таймауты и общий бюджет поиска; план сохраняется без координат при недоступности сервисов.

## Файлы, API и данные

- `server/place-search.js` — новый серверный поиск, фильтрация, нормализация, кэш, fallback.
- `server/plan-parser.js` — интеграция; эвристическое название очищается от дня недели/порядкового дня.
- `server/index.js` — `POST /api/trips/:id/places`, лимит трёх одновременных поисков, сохранение метаданных.
- `public/planner.js`, `public/planner.css` — кэш поездки, варианты, повторный поиск, подписи мест.
- `public/map-drafts.js` — метаданные в существующем предпросмотре.
- `public/openapi.json`, `.env.example` — документация и конфигурация без секрета.
- `tests/place-search.test.js` — новые проверки провайдеров, страны, расширения, выбора, кэша и ошибок.
- `tests/plan-parser.test.js`, `tests/plan-save.test.js`, `tests/mvp.test.js` — актуализация изолированных фикстур и проверка API/метаданных.

Новый endpoint принимает `{query, refresh?}`; город берётся из сохранённой поездки. Ответ: `place`, `candidates`, `status`, `scope`, `source`, `cacheable`. Статусы: `matched`, `choose`, `not_found`, `unavailable`, `no_city`.

`/parse-plans` поддерживает `searchPlaces:false`: только извлечение, чтобы календарь применял отдельный кэш поиска. Без параметра прежний комплексный сценарий сохранён и дополнен вариантами места.

У найденного места остаются `name`, `lat`, `lng`, `address`; добавлены `city`, `countryCode`, `type`, `source`, `distanceKm`, `inCity`, `displayName` и служебные поля выбора. В серверной точке сохраняются компактные дополнительные `city`, `countryCode`, `placeType`, `source`, `distanceKm`; адрес остаётся в `description`. У события — необязательное `placeName` для повторного поиска после возвращения в календарь. Кандидаты остаются в локальном черновике и не создают точки до выбора.

## Проверено

- `npm test`: 22 теста прошли.
- Chrome/Playwright, настоящий локальный API с контролируемыми провайдерами: автоматическое место, два местных варианта, соседний город, живой маркер, localStorage-кэш после перезагрузки, ненайденное место, offline fallback, сохранение метаданных, ширина 390 px без переполнения/ошибок JS.
- Регрессия календаря: автораспределение, занятые слоты, время из текста, перенос списком и drag-and-drop, перераспределение, синхронизация с картой, сохранение, однодневный режим и подтверждение дат — прошла.
- Живой LLM + fallback: «На второй день посетить Казанский кремль после обеда», поездка 12–15 июля 2026 → 13 июля, 14:00, источник `llm`, три варианта Nominatim в Казани. Единственный результат не имитировался: здесь необходим выбор пользователя.
- Пользовательская база и файлы тестами не изменялись.

## Ручная проверка

1. **Место в городе.** Открыть поездку в Казань, подтвердить четыре дня. Добавить «Посетить Казанский кремль на второй день после обеда». Проверить день 2 и 14:00. При нескольких вариантах выбрать рекомендуемый; подпись содержит Казань, на карте появляется маркер. Единственный уверенный результат выбирается автоматически.
2. **Соседний город.** Добавить «Свияжск». Проверить город и расстояние. До выбора нет нового маркера, после выбора — есть. Иногородний вариант не выбирается автоматически. Конкретные результаты зависят от покрытия сервиса.
3. **Ненайденное место.** Добавить выдуманное название. План остаётся в расписании с пометкой «Место не найдено». Сохранить: карта открывается, событие остаётся без геоточки. Вернуться в календарь и проверить «Найти место ещё раз».
4. **Отключённая сеть.** В DevTools заблокировать `/api/trips/*/places` или внешние запросы backend. План и время должны остаться с мягкой подписью. Если недоступен и разбор — работает локальная эвристика. При полностью выключенном backend постоянное сохранение невозможно; черновик остаётся до восстановления сети.
5. **Кэш и согласованность.** Добавить «Посетить Кремль», затем «Сходить в Кремль»: при одинаковом извлечённом названии повторный `/places` не нужен. Повторить после перезагрузки. Другая поездка использует отдельный кэш. Проверить перенос плана, подтверждение дат и переход на карту после сохранения.
6. **Постоянное хранение.** Сохранить выбранные места, перезагрузить карту/календарь: город и название остаются. Проверить карту ↔ таймлайн. В запросах браузера к backend нет API-ключа; он используется только сервером.

`changes/place-search.patch` содержит только изменения этого этапа. `.env`, база и загруженные файлы исключены.
