# Разбор планов через LLM и геокодирование

Существующие календарь, черновики событий, явное сохранение и карта сохранены. На календаре появился блок «Ваши планы». Результат разбора добавляется в редактируемые черновики; существующая кнопка «Сохранить и перейти к карте» фиксирует события и найденные точки вместе.

## Подключение

Документация Spirit: https://docs.pages.t-education.com/docs/docs/ai/llm-proxy/usage

- Проверенный адрес: `https://llm-proxy.spirit.t-education.com/chat/completions`.
- Сервер передаёт ключ как Bearer. Ключ записан только в локальную `.env`, исключённую через `.gitignore`; права файла — 600. Файл не включается в Docker-образ и не доступен через статический сервер.
- `.env.example` содержит только имена настроек и адрес. Для развёртывания задайте `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` в окружении. Локальный Node с `process.loadEnvFile` читает `.env` автоматически; на старом Node передайте переменные через окружение.
- Для предоставленного аккаунта запрос `/models` подтвердил доступность `openai/gpt-6-luna`; модель выбрана в локальной настройке. Формат Chat Completions проверен по https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create .
- Тексты планов отправляются LLM только при нажатии кнопки разбора; поле содержит предупреждение о передаче текста. Билеты и вложения этим запросом не отправляются.

## Поведение

`POST /api/trips/:id/parse-plans` принимает `{text,date}` и возвращает до 8 предложенных событий. До 10 000 символов, таймаут LLM 12 секунд; ошибки авторизации, сети и неверный JSON включают эвристический разбор. Эвристики распознают даты ISO/русские месяцы, «завтра», «послезавтра», время HH:mm, «утром», «после обеда», «вечером», базовые типы событий. Они не заменяют полноценное понимание текста: проверьте результат.

Место геокодируется сервером через Nominatim с названием города, при наличии — предпочтительным прямоугольником вокруг города. Координаты из ответа LLM не используются. Запросы последовательны с интервалом минимум 1,1 секунды, успешные результаты кэшируются в памяти на сутки (до 1000 мест). Общий бюджет геокодирования одного плана — 12 секунд. Геокодирование может вернуть неоднозначное место: перед сохранением доступен выбор существующей точки маршрута. При отсутствии координат сохраняется название места в описании; приложение не создаёт выдуманный маркер.

Исходный текст и предложенные события сохраняются локально как черновик. Повторный разбор того же текста не дублирует те же названия в том же дне. Если время отсутствует, оно остаётся пустым — перед сохранением нужно заполнить его вручную. Ориентировочное время помечается в описании.

Существующий `PUT /api/trips/:id/day-events` минимально расширен: необязательное поле `place` создаёт обычную точку маршрута и связывает её с событием. Модель точки/события прежняя. Координаты проверяются; одинаковые координаты внутри поездки переиспользуются. Невалидная пачка не записывает ни события, ни точки. Ранее существовавшие события других источников не удаляются.

## Проверка

1. Откройте поездку в календаре. Введите «12 июля сходить в Казанский кремль после обеда», нажмите «Разобрать планы».
2. Проверьте черновик на 12 июля: название Кремля, тип «Экскурсия», время 14:00 с пояснением о приблизительности; в дополнительных полях указано найденное место. Год без явного указания берётся из выбранного дня календаря.
3. Измените название/время, сохраните общей кнопкой. Откроется карта с точкой маршрута и событием в таймлайне. Повторное сохранение не создаёт вторую точку с теми же координатами.
4. Перезагрузите календарь до сохранения: исходный текст и события остаются в черновике. Повторный разбор того же текста не добавляет дубль.
5. Для проверки отказа LLM временно задайте неверный `LLM_MODEL` в локальном окружении и перезапустите сервер: базовая фраза разбирается эвристически. Верните настройку после проверки.
6. Для проверки отказа геокодера заблокируйте серверу доступ к Nominatim: событие остаётся без координат, название места видно в описании. Можно выбрать существующую точку или сохранить без неё. DevTools браузера не блокирует серверные запросы к внешним сервисам.
7. Отключите сеть браузера: запрос не проходит, исходный текст и существующие черновики остаются на устройстве, страница не падает.
8. Проверьте Network: браузер обращается к локальному `/api/trips/:id/parse-plans`, заголовка с ключом LLM нет. `GET /.env` возвращает 404; `git check-ignore .env` подтверждает исключение файла.

## Выполнено

- Живой вызов LLM вернул название, дату, тип и время для Кремля. Отдельный живой запрос Nominatim вернул его координаты.
- `npm test`: 6 тестов, включая fallback, отсутствие координат от LLM, кэш геокодера и интеграцию сохранения на изолированной базе.
- Chromium, ширина 390 px: разбор → черновик → перезагрузка → защита от дублей → ошибка API без потери данных → сохранение → карта и таймлайн; горизонтального переполнения и ошибок JavaScript нет. API браузерной проверки подменён, пользовательская база не изменялась.
- Проверены синтаксис JavaScript, `git diff --check`, исключение секрета из Git и недоступность `.env` через HTTP.
