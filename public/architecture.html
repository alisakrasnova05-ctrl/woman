Архитектура explore.

Приложение для планирования поездок. Сервер и интерфейс работают на встроенных возможностях Node.js и браузера без сборки и обязательных npm-зависимостей.

Браузер
  ├─ public/*.html, *.css, *.js
  └─ REST /api/*
        ↓
Node.js HTTP сервер (server/index.js)
  ├─ CRUD и фильтрация по поездке
  ├─ разбор планов (server/plan-parser.js)
  ├─ JSON persistence (data/db.json)
  └─ фотографии (data/uploads/)

Компоненты

  • server/index.js — HTTP-маршруты API и раздача статических файлов. Использует встроенные модули Node.js.
  • server/plan-parser.js — извлекает события из текста, при настройке использует LLM, затем пытается определить координаты мест через Nominatim.
  • public/ — клиентские страницы поездок, календаря и маршрута; JavaScript обращается к REST API через fetch.
  • data/db.json — хранит поездки, точки, события и перемещения. data/uploads/ хранит загруженные изображения.

Хранение и область данных

Точки, события и перемещения могут быть привязаны к поездке через tripId. Для их API-запросов передавайте ?tripId=…; сервер изолирует данные поездок при чтении и записи. Записи без tripId относятся к старым данным.

Данные сохраняются в JSON-файле целиком при изменениях. Для многопользовательской production-системы этот слой можно заменить транзакционной базой данных и объектным хранилищем.

Внешние сервисы

  • Поиск городов — Open-Meteo Geocoding API; для ряда популярных городов есть локальный резервный список.
  • Поиск координат распознанных мест — Nominatim. При недоступности сервиса событие возвращается без координат.
  • Разбор планов через LLM включается переменными LLM_API_KEY, LLM_BASE_URL и LLM_MODEL; без них работает эвристический разбор.
  • Карта использует Leaflet и тайлы OpenStreetMap в клиентской части.
